# CS-002: Suspicious User Creation

## Что это за инцидент

После серии неудачных SSH-атак на сервере Debian была создана новая
учётная запись `hacker`, которую сразу добавили в группу `sudo`.
Wazuh распознал это как **цепочку атаки** и создал алерт
критического уровня — правило 40501 (Level 15).

Это самый серьёзный инцидент из трёх в моей лаборатории.

## Основные данные

| Параметр | Значение |
|---|---|
| Дата | 2026-10-08 |
| Жертва | Debian 13 (192.168.0.9) |
| Атакующий | Локальный sudo + следы SSH brute-force с Kali |
| Уровень критичности | **Critical (Level 15)** |
| MITRE ATT&CK | T1136.001 — Create Account: Local Account |
| Доп. тактики | Persistence, Privilege Escalation |
| Статус | Закрыт, компрометация в рамках лаборатории |

## Что произошло

Сценарий описывает **цепочку атаки**:

1. **Сначала** — серия неудачных SSH-попыток (это был CS-001).
2. **Потом** — на сервере появляется новая учётная запись `hacker`.
3. **И сразу** — её добавляют в группу `sudo`, давая права root.

Именно такая **последовательность** (атаки → создание пользователя)
и является тревожным сигналом. По отдельности эти события могли бы
быть легитимными. Но вместе — это классический признак того, что
атакующий смог войти и закрепляется в системе.

## Что заметил Wazuh

Wazuh сгенерировал несколько алертов:

| Rule ID | Level | Что означает |
|---|---|---|
| 5902 | 8 | Создан новый пользователь в системе |
| 5555 | 3 | Пользователь сменил пароль |
| 5402 | 3 | Успешное выполнение sudo от root |
| 5403 | 4 | Первое выполнение sudo новым пользователем |
| **40501** | **15** | **Атаки, за которыми последовало создание пользователя** |

**Правило 40501** — это композитное правило. Оно срабатывает только
тогда, когда Wazuh видит **последовательность**: серия атакующих
событий → затем создание пользователя. Именно поэтому оно имеет
максимальный уровень критичности (15).

Это правило — пример **корреляции событий**. Wazuh не просто
смотрит на отдельные логи, а связывает их во времени и делает
вывод о вероятной атаке.

## Доказательства

Из лога на Debian:

```
useradd[XXXX]: new user: name=hacker, UID=1001...
```

Поля, которые важно смотреть в алерте:
- `data.dstuser` = `hacker` — имя созданной учётки
- `rule.id` = `40501` — композитное правило
- `rule.level` = `15` — критический уровень
- `full_log` — полная строка события

## Хронология (UTC)

| Время | Событие |
|---|---|
| 23:08:34 | Создан пользователь `hacker` (rule 5902) |
| **23:08:34** | **Сработало правило 40501 (Level 15) — атаки + создание пользователя** |
| 23:08:46 | Выполнено sudo от root (rule 5402) |
| 23:08:54 | Пользователь сменил пароль (rule 5555) |

Обрати внимание: правило 40501 сработало **в ту же секунду**,
что и создание пользователя. Wazuh уже «держал в голове» предыдущие
SSH-атаки и мгновенно связал события.

## Что я сделал

1. **Проверил, легитимно ли создание пользователя.** В лаборатории
   это была моя тестовая активность — но в реальной среде это был бы
   первый вопрос: «Кто это сделал и зачем?».

2. **Проверил, не было ли успешного SSH-входа под новой учёткой.**
   Поискал в `auth.log` успешные логины за `hacker` — их нет.

3. **Проверил сессии и sudo-логи.** Убедился, что учётка
   использовалась только локально и только в рамках теста.

4. **Оценил уровень риска.** Если бы это была реальная среда —
   эскалация на L2 с изоляцией хоста была бы обязательной.

5. **Зафиксировал рекомендации** (см. ниже).

## Рекомендации

Что стоит сделать, чтобы защититься от таких сценариев:

| Приоритет | Что сделать |

## Итог

| Параметр | Значение |
|---|---|
| Ложное срабатывание | Нет |
| Компрометация | Да (в рамках лабораторного сценария) |
| Требуется эскалация | В продакшене — да, на L2 |
| Качество детекта | Отличное — композитное правило поймало цепочку атаки |
| Статус | Закрыт |

Инцидент демонстрирует, как SIEM обнаруживает **связанные события**,
которые по отдельности могут выглядеть безобидно. Правило 40501
уровня 15 — это сигнал, который в реальной SOC-команде требует
немедленной реакции.

## Чему я научился

1. **Композитные правила — сила SIEM.** Wazuh умеет связывать
   события по времени и по хосту. Правило 40501 — отличный пример:
   оно не сработало бы ни на брутфорс отдельно, ни на создание
   пользователя отдельно. Только вместе.

2. **Уровень алерта имеет значение.** Level 15 — это максимальный
   уровень. Такие алерты никогда не остаются без внимания.

3. **MITRE помогает классифицировать.** T1136.001 — «Create Local
   Account» — это техника Persistence. Атакующий создаёт учётку,
   чтобы вернуться в систему позже.

4. **Kill chain в действии.** В одном кейсе видна последовательность:
   Credential Access (brute-force) → Persistence (создание учётки) →
   Privilege Escalation (добавление в sudo).
